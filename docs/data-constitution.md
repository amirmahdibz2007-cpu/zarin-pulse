# قانون اساسی داده

دانهٔ حقیقت محصول جلسه (`session_key`) است، نه ردیف تلاش. درآمد، سفارش، سبد خرید و دفتر اثر فقط روی جلسه محاسبه می‌شوند.

## دانه‌ها

| دانه | تعریف |
| --- | --- |
| try | یک ردیف فایل خام |
| session | یک `session_key` یکتا |
| order | جلسه با `session_status = Verified` |
| customer | جفت `(merchant_key, payer_card_key)` |
| winning_try | تلاشی با `try_status = Verified` |

## وضعیت پایانی جلسه

1. اگر `min_try_seq = 0` → `NoAttempt`
2. وگرنه اگر حداقل یک تلاش `try_status = Verified` دارد → `Verified`
3. وگرنه آخرین `try_status` جلسه (`InBank` / `Failed` / `Paid` / `Reversed`)

`NoAttempt`، `InBank` و `Failed` سه چیز جدا هستند و در هیچ متری با هم جمع نمی‌شوند.

## قواعد اجباری

- موفقیت تلاش فقط با `try_status = 'Verified'` تعیین می‌شود. `verified_at` روی همه ردیف‌های یک جلسه موفق کپی می‌شود و نشان نمی‌دهد کدام تلاش برنده بوده.
- برای درآمد و شمارش سفارش، `session_status` مرجع است. ۲۸ جلسه اختلاف بین این دو ستون در صفحه تطبیق اعداد نمایش داده می‌شود.
- مبلغ در داخل یک `session_key` یکتا است. ادعای ETL: صفر جلسه با `COUNT(DISTINCT amount) > 1`.
- `adjusted_fee` کارمزد واقعی نیست. کارمزد جلسات ناموفق فقط با برچسب «بالقوه» و هرگز به‌عنوان برداشت.
- `settled_at` برای تحلیل تسویه ممنوع است (برابر `verified_at`).
- `issuer_bank_code` برای مقایسه بانک ممنوع است (سوگیری انتخاب).
- `expire_in` به‌عنوان متغیر تبیینی ممنوع است (صفر واریانس).
- `switch_response_code` فقط در Passport (پرشدگی ۲٫۶٪).
- جلسات باند مبلغ `1e3` علامت آزمایشی می‌خورند و از تحلیل رفتاری خارج می‌شوند.
- ۱۹ روز کم‌پوشش از خط پایه حذف می‌شوند و در UI به‌شکل شکاف دیده می‌شوند.
- ماه ناقص با برچسب و نرمال‌سازی به ازای روز فعال.

## پوشش زمانی

`created_at` از 2026-01-01 تا 2026-06-30. `verified_at` حداکثر 2026-07-11. میانه روزانه ۱۱٬۶۸۸ جلسه. روز کم‌پوشش: جلسه روزانه < ۰٫۵ × میانه.
