# اصلاحیه اسپک

هر جا داده با سند قبلی فرق داشت، داده برنده است. این فایل همان تصمیم‌ها را نگه می‌دارد.

## 2026-08-20 — فرمول روز هفته جلالی

اسپک نوشته بود `jalaliWeekday = (gregorianWeekday + 2) % 7` با صفر = شنبه.

`2026-01-10` شنبه میلادی است (`Date#getUTCDay() = 6`). با `+2` به ۱ می‌رسد که یکشنبه است.

فرمول زنده: `(getUTCDay() + 1) % 7` تا شنبه = ۰. جدول طلایی تاریخ‌های جلالی عوض نشده.

## 2026-08-20 — اثر تعرفه M106

اسپک در بخش ۳٫۷ نوشته بود انتظاری ۲٫۵۲۴٪ و اثر تعرفه ۵٫۵۸۹٪. همان سند در بخش ۹ مرجع را `SUM(adjusted_fee)/SUM(amount)` روی باند `FLOOR(LOG10(amount)*4)/4` تعریف می‌کند.

خروجی همان SQL روی داده: نرخ واقعی M106 برابر ۸٫۱۱۳٪ است، نرخ مرجع باند حجم‌وزن‌شده حدود ۵٫۹۴٪، اثر تعرفه حدود ۲٫۱۷٪. عدد ۲٫۵۲۴٪ به میانگین غیروزن‌دار نرخ پذیرنده‌ها در باند صحیح `1e5` نزدیک است، نه به فرمول بخش ۹.

طبق قاعده ۶، SQL بخش ۹ و داده برنده‌اند. سرتیتر محصول نرخ واقعی ۸٫۱۱۳٪ و اثر تعرفه مثبت را نشان می‌دهد.

## 2026-08-20 — پوشش همتا و کل قابل بازیابی

تعریف نهایی همتا (همان صنف + دهک مبلغ میانه ±۲ + حداقل ۵ همتا) روی این پیاده‌سازی **۱۵۲ از ۱۵۶** پذیرنده واجد شرایط را پوشش می‌دهد، نه ۱۵۴. آستانه پذیرش ETL همان ≥۱۵۰ است.

کل فروش قابل بازیابی با `capture_rate=0.5` برابر **۴۲۶٫۷ میلیارد ریال** شد، در برابر ۴۱۶ میلیارد بخش ۱۱. اختلاف از جزئیات صدک ۷۵ گروه همتا است. عدد زنده artifact ملاک UI است.
